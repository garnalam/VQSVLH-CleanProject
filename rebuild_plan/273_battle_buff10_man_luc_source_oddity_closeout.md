## Easy Mechanism

`Man Luc` sounds like an attack-up buff from the user-facing text, but the
source data says otherwise.

The original buff row stores `paramA = -1`. The original code uses that number
literally:

```text
storedValue = baseAttack * -1 / 100
currentAttack = baseAttack + storedValue
```

With a clean smoke stat of `baseAttack = 100`, the source-shaped result is:

```text
attack: 100 -> 99
sample damage: 80 -> 79
```

This is not a rebuild guess and not a decode artifact. It is a contradiction
between source text and source data/code. Do not change it into a positive
attack-up without an explicit gameplay-deviation decision.

## Source Chain

Buff row:

```text
aq.c[6][10] = [343,358,2,-1,-1]
```

Meaning:

```text
nameTextId=343
descriptionTextId=358
duration=2
paramA=-1
paramB=-1
```

Producer skills:

```text
skill62 = [6,179,591,80,0,45,1,10,5,0]
skill68 = [6,185,597,110,3,15,1,10,5,0]
```

`game.d.q()` handles skills `21,27,42,48,62,68` with:

```java
d2.h.a((byte)aq.c[1][n2][7], -1, n2);
```

For `62/68`, that means:

```text
buffId=10
value=-1
sourceSkill=62 or 68
```

`game.b.a(byte,int,int)` case `10` then ignores the passed value and source
skill parameter:

```java
this.v[by][1] = (short)(this.c[2] * aq.c[6][by][3] / 100);
this.d[2] = (short)(this.c[2] + this.v[by][1]);
```

`game.b.o(int)` case `10` reasserts the same stored value each tick:

```java
this.d[2] = (short)(this.c[2] + this.v[n2][1]);
```
